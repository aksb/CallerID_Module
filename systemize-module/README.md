# Aksb2026CallerID 系统化增强（可选，风险自负）v4.3

和保活脚本模块（`callerid_keepalive`）完全独立的另一个模块，两个装不装、
先后顺序都互不影响。

## v4.3 相对 v1.0 的变化（重要，务必看一下）

v1.0 的做法是刷机时现场找到手机上已装的 APK、复制到系统分区、再
`pm uninstall -k` 卸载当前安装。**实测中这个做法会导致部分设备重启后
出现桌面图标变成默认安卓机器人、App 打不开（闪退）、且此后连重新安装
APK 都会失败的问题**，且这个问题一旦出现，不是靠重装 APK 能解决的，需要
先移除本模块、彻底 `pm uninstall`（不带 `-k`）清干净再重装。

v4.3 改成参照 [RecordYou](https://github.com/you-apps/RecordYou-Magisk-Module)
的思路：模块内置一个跟正式 APK 用**同一套签名**、但没有任何真实功能、
也没有桌面图标的"占位 APK"，刷机时原样复制进系统分区，**不再做任何
"卸载现有安装"的操作**。这样一来：

- **不再要求"先装 App 再刷模块"这个顺序**，随便哪个先装都可以；
- 后续不管是先装 APK 还是先刷模块，Android 都会把正式 APK 当成"给这个
  系统应用做更新"来处理——这是安卓系统给预装应用推送更新时天天在用的
  原生机制，不再依赖本模块脚本去做有状态的现场操作，从根上避免了 v1.0
  那个问题。

## 前提条件（这一版新增的唯一硬性要求）

占位 APK 和你手机上安装的正式 APK，**必须是同一套签名**。只要你安装的
是从这个项目官方 Release 页面下载的 APK，这个条件天然满足（占位 APK 和
正式 APK 用的是同一个 CI 流程、同一把签名 key 打出来的）。**如果你是拿
自己另外编译、用不同签名 key 签过的 APK，这套机制就不适用**，会出现
签名不一致导致无法互相识别成"更新"的情况（不会导致 v1.0 那种损坏性
故障，只是装不上而已，卸载模块或者卸载 APK 重来即可）。

## 这个模块做了什么

`customize.sh` 把模块内置的占位 APK 复制到 `/system/priv-app/Aksb2026CallerID/`，
仅此而已，不涉及任何 `pm install`/`pm uninstall` 操作。占位 APK 本身：

- 包名跟正式 APK 完全一样（`com.aksb2026.callerid.module`）；
- 没有任何 Activity，不会出现在桌面上，装了之后、正式 APK 装上去之前，
  它在系统里是完全不可见、不可交互的；
- 变成系统应用后能拿到 priv-app 相关待遇。**v4.3 起不再声明
  `android:persistent="true"`**——这个属性一旦真正生效，安卓会直接禁止
  再用 `pm install` 更新这个包名（报错 `Persistent apps are not
  updateable`），跟这个模块"顺序无关、随便装随便更新"的目标是直接冲突的，
  实测也确认踩到过这个限制，所以从 v4.3 起去掉，只保留"变成系统应用"
  这部分效果。

## 安装

顺序随意：

- **先刷模块、再装 APK**：刷完重启，正常安装正式 APK 即可，会被系统当成
  给这个系统应用做更新来处理。
- **先装 APK、再刷模块**：刷完重启，系统会自动识别成"系统应用 + 已被你
  现有安装覆盖更新"，不需要你做任何额外操作。

## 遇到异常怎么办

刷完重启后如果 App 打不开、提示安装包无效等异常：

1. Magisk App 里移除这个模块，重启；
2. `adb shell pm uninstall com.aksb2026.callerid.module`（**不带** `-k`，彻底清干净）；
3. 重新正常安装正式 APK，确认恢复正常即可。

## 卸载

Magisk App 里移除这个模块，重启。移除后系统分区的占位 APK 会消失，如果
你的正式 APK 当时是以"系统应用的更新"这种形式存在，重启后它会变成什么
状态（正常降级成普通应用，还是被系统一并清掉）跟具体安卓版本/ROM 有关，
我们没有十足把握打包票——如果发现异常，参考上面"遇到异常怎么办"处理。
